# Single-cell Transcriptomics for immuno.games

A focused English learning course for immuno.games and CSBL. Version 1.0.0, 7 September 2026.

The course contains 15 lessons in five blocks, 17 short learning steps, 96 questions, 10 interactive learning activities, optional mastery challenges, block trophies and a final investigation. The main technology is 10x Chromium 3′ gene expression and the main analysis environment is Seurat. Other technologies are briefly acknowledged, not taught as parallel pipelines.

## Publish on your existing GitHub Pages site

Copy the `single-cell` folder from this archive into the directory already published by your immuno.games repository. Commit the addition using your existing publishing workflow. If that directory is published at the domain root, the course address will be `https://immuno.games/single-cell/`.

Keep all files in the folder together. Do not replace your existing homepage, domain configuration or the spatial course. Relative assets and hash-based navigation allow this course to run in another subdirectory too. No build, npm installation, backend, API key or database is required.

To try it locally, open `single-cell/index.html` in a modern browser. The separately delivered `single-cell-transcriptomics.html` embeds the same scripts and images in one file. Local-file browser storage and sharing support vary; HTTPS hosting provides the normal experience.

## Learning scope

The pipeline teaches files and objects, sparse data, QA, QC and filtering, scDblFinder, SoupX, LogNormalize with SCTransform as an alternative, variable features, PCA, Harmony when justified, Leiden, UMAP and annotation. Condition comparisons distinguish proportions from expression: propeller and optional scCODA for composition, donor-aware pseudo-bulk with edgeR for condition DE, and Wilcoxon for exploratory markers. TMM belongs to the pseudo-bulk workflow rather than being a third single-cell exploratory normalization. CellChat and Slingshot each illustrate one inference task and its limits.

These are established representative choices, not an audited usage ranking or a claim that one method is universally best. No imputation, mandatory batch correction, universal QC threshold or exhaustive tool catalog is taught.

## Real data versus teaching simulations

The UMAP explorer includes 2,638 retained cells from the public 10x PBMC3k dataset, using the processed reference distributed by Scanpy and cellxgene. Two UMAP layouts were recomputed from the first 20 stored PCA components, with random seed 42, Euclidean distance and parameter pairs (10 neighbors, minimum distance 0.1) and (40 neighbors, minimum distance 0.6). Supplied broad labels are preserved. They were not revalidated or generated by the Seurat commands in the course.

This is an older processed reference, including its original filtering, normalization and regression choices. It demonstrates how the same input can have different UMAP geometry; it is not presented as a new recommended preprocessing recipe. The original 10x dataset is licensed under CC BY 4.0. Attribution and source links appear in Resources and the figure captions. `DATA-PROVENANCE.json` records the exact downloaded file hash, processing input, UMAP version and seed. `source/prepare_pbmc.py` reproduces these visualizations using Python with h5py, numpy, umap-learn and matplotlib. The raw 25 MB reference file is not required by the site and is not bundled.

The QC table, composition counts, normalization example, pseudo-bulk arithmetic, DEG table, signaling evidence ladder and trajectory graph are explicitly synthetic. The trajectory activity changes distance from a root on a fixed graph; it does not execute Slingshot. The game does not execute Seurat, edgeR or CellChat, and it does not analyze user-uploaded experimental data. It links to real public tutorials for those workflows.

## Progress and privacy

Correct lesson, case and final-investigation decisions earn 10 XP once, up to 710 XP. Repeating a solved question does not add points. A block trophy requires all of its lesson questions and its three-question case. Optional mastery uses five different questions with a 4/5 threshold and no extra XP. The final investigation unlocks after five trophies; 4/5 earns course completion. Best scores survive retries.

Progress uses the independent browser key `immunogames:single-cell-essentials:v1`. It does not overwrite spatial-course progress. JSON export/import validates compatible records and merges achievements. Local records are editable by their owner and are not verified assessments or professional certificates.

There are no accounts, analytics, remote AI calls, external fonts or tracking services. The optional learner name remains local and appears only in exports or cards the learner chooses to create. Sharing generates a PNG and text; it never publishes automatically. Native sharing and clipboard behavior depend on browser support. Downloads provide a fallback.

## Maintain or adapt the course

`course.js` stores lessons, questions, references and the glossary. `engine.js` defines progress rules. `app.js` renders the course and achievements. `labs.js` contains the interactive activities and their pure arithmetic models. `pbmc.js` stores the compact public-data display arrays. `styles.css` defines responsive styling. `assets` contains the generated UMAP figures and icon.

`source/build_course.py` regenerates the current course content. Keep IDs stable for compatible content edits. Use a new course ID for bulk transcriptomics or other courses; increase the content version for incompatible question changes and implement a migration if existing progress should be retained.

## Verification and limits

Run `node verification/check.cjs` from this extracted archive. It checks all 96 question records, scoring and repeat attempts, trophy requirements, mastery and final thresholds, progress validation and round trips, route rendering, restored completion, interactive arithmetic, local figures and both UMAP arrays. JavaScript syntax is also valid. The two generated scientific figures were visually inspected.

Route checks use a lightweight JavaScript harness rather than a browser. A real desktop/mobile browser and native sharing were not exercised in this environment. Before announcing the public course, check the published site on the intended devices, including progress export/import and card download.
